# 首次连接与存储选择

Skill 是整理和使用记忆的工作规则，不自带存储、账号或令牌。安装后不需要重复安装插件；先确定用户打算把记忆存在哪里。

## 已有工具或仓库

- 已有 MemHarbor MCP：使用其真实 schema。多个连接时以用户指定的服务为准；不把相似名称视为同一份数据。只读入口仍可查找、读取和整理草稿。
- 已明确授权的私有 Git 工作副本：按 T0 操作。用户需要给出确切 vault 路径；不能擅自把当前软件项目或私人目录变为记忆仓库。
- 两者都没有：先整理可审阅草稿，默认介绍独立本地 Git vault，说明需要指定目录和访问权限；用户明确选择 MCP 时再按下文连接。未能访问存储前，不声称已查重或保存。不要求用户手填主题 UUID 或提交 SHA。

独立本地 vault 可跨会话保留文件和 Git 历史，但仅在本机；没有远端不等于 GitHub 已备份。创建目录、Git 初始化及首次提交应包含在用户指定的位置和授权范围内。若缺少 Git 作者身份，请用户配置该仓库的身份，不猜测个人姓名/邮箱，不改全局 Git 配置。

## 用户选择 MCP 时

- T1：本机 Node.js 22+ stdio；客户端直接启动构建后的 `dist/local/main.mjs`。进程使用 `GITHUB_OWNER`、`GITHUB_REPO`、`GITHUB_TOKEN`（数据仓库 PAT），默认分支 main、默认只读；保存需要 `MEMORY_ACCESS=write` 和 PAT 写权限。
- T2：已有 HTTPS `/mcp` 地址和 MemHarbor 读/写令牌。客户端不需要也不应接收服务端 GitHub PAT。
- `--demo`：只有当前进程内的合成练习数据，退出或重连后丢失。明确报告临时保存，不能声称以后可继续读取。不要自动切换用户的真实连接来演示。

令牌由用户通过客户端环境或凭据管理配置，不索取到对话中，不写入记忆或 Skill 文件。遵守用户对客户端配置变更的授权；服务报错不能自动切换到另一存储或直接写 Git 绕过。

连接后先只读调用 list/search。首次持久保存按主流程展示草稿、按授权写入，再回读；写权限不是保存授权。新服务列表为空是正常结果。默认搜索只匹配元数据，正文词查不到时按明确路径或标题定位并读取，不声称资料不存在。

T0 安装与首次使用见源码中的 `docs/FIRST_USE.md`（中文）或 `docs/FIRST_USE.en.md`（English）；已有服务的客户端配置见 `docs/MCP_CLIENTS.md`。若没有源码，仍可凭此文和随附操作/格式契约使用已授权的 T0 或 MCP 入口。
