# 共用 vault 与内容契约

T0 是 Agent 使用已授权文件工具或 Git 工作副本直接管理私有 vault；T1 是本机 stdio 服务；T2 是 Worker/R2 服务。明确独立、未接入服务的 T0 vault 以本地 Git 为权威源，可以没有远端；没有远端时不要求推送，也不代表已经备份。T1/T2 及与它们共享的 vault 仍以 GitHub 私有仓库为权威源，清单和缓存可重建。不要因当前客户端没有 MCP 就认定整个仓库只供 T0 使用。

## 文件与身份

主题在 `<path>/`，CONTEXT.md 必需；STATE.md、DECISIONS.md、TODO.md、SOURCES.md 可选。沿用服务格式的路径、NFC、状态与大小限制；默认单文件不超过 262144 UTF-8 字节，正文不截断。CONTEXT 前导 BOM 不合法。其他正文保留原 BOM、换行和字节，不为整理而改写。

YAML 仅允许 id/path/title/status/description/aliases/tags；不增加时间、来源或关系字段。与 T1/T2 共用的 T0 vault 必须创建合法小写 UUID，用可靠生成器，不用示例 ID。只有明确独立的 T0 vault 才可暂缺 id、使用 null 或空字符串。已有合法 UUID 永不重分。

需要身份迁移时显式运行项目的 `scripts/migrate-memory-ids.mjs <repo>` 预览；`--write` 全量校验后写入。脚本不提交、不推送、不移动目录，不在启动或升级时自动执行。写后再次预览应为零变更；用户一次提交全部迁移并非强制推送后才接入服务。规范 UUID/schema 3 vault 不需要迁移。

## 可选 INDEX.md

仅 T0 维护。先用目录/树能力；无法枚举时才参考根清单。无清单且无法枚举时请用户指定路径，说明范围；清单缺行不证明不存在。

```markdown
# Memory Index

<!-- memharbor-index:v1 -->

| path | title | status | aliases | tags |
| --- | --- | --- | --- | --- |
| 工作/网络 | 网络基础设施 | active | ["网络配置"] | ["网络"] |
```

固定五列，行按 JavaScript 默认字符串顺序排序 path。aliases/tags 先用 JSON.stringify 序列化字符串数组（空值 `[]`）；每个单元格再依次转义：反斜线为 `\\`、竖线为 `\|`、实际 CR/LF 为 `\r`/`\n`。解码时逐字符处理反斜线转义，再对数组单元格 JSON.parse；不能直接按所有竖线切分。字段从 CONTEXT 派生，不反向覆盖源信息。

只有完整枚举并读取元数据后才可创建完整清单。缺少标记的既有 INDEX.md 不覆盖。已启用清单时，新建、移动、删除或改变 title/status/aliases/tags 须与清单同 commit；正文或 description 修改不更新清单。未启用时不强制创建。T1/T2 不维护它，切回 T0 时视为可能陈旧，能枚举则重建，否则声明局限。

## 时间、证据与失败经验

CONTEXT 保存稳定背景和条件；STATE 保存当前状态与必要结果；DECISIONS 保存选择、理由、替代关系及有复用价值的失败；TODO 保存待验证行动；SOURCES 保存可定位证据。

重要结论按需记录对象/环境、生效或失效时间、记录/核验时间、证据状态、来源及替代关系。未知日期省略或标未知；Git 提交时间不能替代生效时间。区别已验证、用户陈述、推断、待验证、争议、已被替代，不新增 topic.status 枚举。

用主题内稳定来源编号或锚点对应具体结论和 SOURCES 中的实际链接、文件及已知版本、对话定位；无可用链接则如实记录。编号不是全局身份，旧记忆不用批量补齐。updated_at 不是访问/核验时间；相同内容仍 noop，不能靠重写刷新。实际核验信息只有在保存授权范围内才记入正文。

失败经验包含尝试、环境与前提、结果证据、失败或否决原因及重试条件。一次环境特定的结果不推广为通用规则。压缩过程时保留例外、来源和后续有效修改，不自动全库整理。
